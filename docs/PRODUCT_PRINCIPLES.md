# Product Principles

MATERIAL is an experimental moving-image instrument. Build a visual system,
explore what it can become, then play it. Product choices should strengthen
that experience.

1. **Image first.** Viewport leads; controls support the image.
2. **Immediate.** Creative input gives visible feedback without delay.
3. **Playable.** Useful systems can be performed, not only configured.
4. **Discoverable.** Users can reach worthwhile results without mastering internals.
5. **Reversible.** Experiment, audition, pin and return without losing good states.
6. **Deterministic.** Same project, seed and frame time reproduce same image.
7. **Finite.** Prefer clear limits and curated choices over unlimited graphs.
8. **Progressive.** Show simple controls first; disclose depth when needed.
9. **No dead ends.** Interesting states should be easy to preserve, compare, morph,
   explore and export.
10. **No prestige features.** Build only what improves making, discovering,
    performing, preserving or exporting visual systems.

## Decision check

Before prioritizing work, ask:

- Does this make MATERIAL more playable, discoverable, expressive, immediate or reliable?
- Does it preserve determinism, reversibility and existing project files?
- Can an existing system do this with less new code?

If all answers are no, do not prioritize it for 1.0. See
[V1_PLAN.md](V1_PLAN.md) for sequencing and explicit scope.
