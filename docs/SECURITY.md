# Security model

MATERIAL is a local, offline-first desktop application. It has no accounts, no
network services and no telemetry. This document states what it does with
content it did not write, which since v0.5 includes shader packs.

## The renderer has no ambient authority

The preload exposes a fixed allow-list of IPC channels — open a media dialog,
read a project, list shader packs — and nothing else. There is no `fs`, no
`require`, no `child_process`, no path API and no generic invoke. A capability
that is not on that list does not exist for the renderer, and adding one is a
deliberate act with a test attached.

Everything that touches the filesystem runs in the main process.

## Shader packs

**A pack is data + GLSL + metadata. It is never executed as code.** The manifest
schema has no field for a script, an entry point, a module or markup, and a test
asserts it stays that way. Unknown fields are ignored rather than kept, so a
manifest from a later version still loads without carrying anything unknown
into the app.

### What a pack can do

Declare shaders, declare parameters, declare presets over its own parameters.
That is the entire surface. Every control a pack appears to add is generated by
MATERIAL from the metadata — a pack supplies no React, no HTML and no CSS.

### Path handling

Two independent checks, because they catch different things:

1. **Lexical**, before touching the disk: `..` segments and absolute paths are
   refused by the schema.
2. **`realpath`**, before reading: a symlink whose target lands outside the pack
   is refused. It passes every lexical check and looks entirely innocent until
   it is followed.

Installing copies **only the files the manifest declares**, so an allow-list
falls out for free and nothing incidental in the folder travels. Removal
resolves the pack id inside the managed root and refuses anything that escapes.

### Bounds

Shader source 256 KB · manifest 256 KB · 64 shaders per pack · 32 parameters
per shader · 512 directory entries scanned. A pack that exceeds one is refused
with a reason.

### What this does NOT protect against

**Arbitrary GLSL can still be expensive.** MATERIAL refuses the obvious
accidents — `while (true)`, `for(;;)`, a redeclared host identifier, a
pack-chosen `#version` — but a well-formed shader can still ask the GPU for
more work than it can do. There is no way to time out a shader invocation from
the host, and MATERIAL does not claim one. A pathological shader can stall or
crash the graphics context; the app recovers by rebuilding from the stored
definition, but the frames in between are lost.

Install packs from people you trust. That is a real limitation, stated plainly
rather than implied away.

## No new surface in v0.5

- No preload API was added for shaders themselves — only four narrow pack
  channels that exchange validated data.
- No `eval`, no `new Function`, no dynamic `import()` of pack content, and no
  CSP relaxation. GLSL is compiled by the GPU driver, which is not JavaScript
  execution.
- No pack content crosses a network boundary, because MATERIAL makes no network
  requests.
- The Output window receives shader **definitions** as low-frequency
  configuration and compiles locally. No compiled program and no pixel ever
  crosses that channel.

## Media and projects

Project files are validated by schema on load; an unknown technique or source
id degrades to a clearly-labelled placeholder rather than throwing. Media paths
come from the user through a system dialog or a drop, and are resolved in the
main process.

## Permissions

Camera, screen and window capture are intent-gated: the permission is armed by
an explicit user action and disarmed when that source stops. Shader
extensibility added no new permission requirement.

## v0.8 — a show that travels

Two channels were added, and both were shaped so the capability does not become
a way to read the disk.

- **`media:pick-folder` opens its own dialog.** The renderer never names a
  directory; the only folders ever walked are ones a person pointed at in
  Finder. The walk is bounded to three levels and 2000 files, skips dotfiles,
  and does not follow directories by symlink.
- **`media:collect` copies only between two constrained ends** — paths the
  project already references, into `<project>/media/`. Both are validated by
  the same `pathArgSchema` every other path argument uses.

No preload API beyond those two. No new permission. No network. Media paths
stored relative to the project resolve in the main process, which already owned
every path in the app; the renderer's view is unchanged and still absolute.
